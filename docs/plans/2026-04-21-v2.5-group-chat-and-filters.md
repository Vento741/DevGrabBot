# v2.5 — Групповой чат для PM + платформенные фильтры

**Статус:** реализовано (2026-04-21)
**Автор задачи:** Денис (web-dusha)
**Триггер:** PM (Кирилл) жалуется что заявки не сыпятся, нет возможности самому брать заявки, платформенные настройки — только on/off галочка без фильтров.

## Цели

Две параллельные фичи:

### A. Групповой чат как параллельный канал для PM
- Все analyzed-заявки публикуются в группу `-1003648962522` **до матчинга**
- Короткая карточка с бейджем платформы, релевантностью, бюджетом, материалами
- Inline-кнопки для PM: `Взять себе`, `Анализ`, `Материалы`, `Открыть`, `Скрыть`
- DM-рассылка разработчикам по стеку **сохраняется** как есть
- `skipped` автоматом **не ставится** — его ставит либо PM через `🗑 Скрыть`, либо группа отключена и нет матчей

### B. Двухуровневые платформенные настройки с фильтрами
- Уровень 1: список платформ с чекбоксом on/off и кнопкой "Настроить →"
- Уровень 2: экран фильтров платформы с `[изменить]` на каждом поле
- Глобально (не per-user), хранится в `Setting(key="platform_config:<platform>")` как JSON
- Multi-select подкатегорий Kwork (fallback-дерево, API TODO)

## Архитектурные решения

| Решение | Обоснование |
|---|---|
| PM "Взять себе" = `OrderAssignment(developer_id=pm.team_member_id)` | PM — это `TeamMember(role=manager)`, FK без check constraint по роли; минимум изменений моделей |
| FIFO race dev vs PM | Сохраняем текущую simple logic |
| Короткая карточка в группе (не полная) | TG limits + spam-защита; полный анализ — по кнопке `📄 Анализ` в DM |
| Фильтры глобально, не per-user | YAGNI — per-user откладывается на v2.6 |
| `min_budget` + "договорная" → включать | Заказчик часто торгуется; `include_no_budget` флаг регулирует поведение |
| Kwork категории через fallback-дерево | `pykwork.get_categories()` отсутствует; fallback с 9 IT-подкатегориями |
| Фильтры скрыты от обычных dev | По роли `TeamRole.manager` или `ADMIN_TG_ID` (Денис) |

## Callback-префиксы

| Префикс | Где | Назначение |
|---|---|---|
| `pmg:take:{order_id}` | группа | PM берёт себе |
| `pmg:analysis:{order_id}` | группа | Полный AI-анализ в DM |
| `pmg:materials:{order_id}` | группа | Материалы в DM |
| `pmg:hide:{order_id}` | группа | Удалить карточку из группы |
| `pmg:info:{order_id}` | группа | Alert "кто взял" |
| `mplat:*` / `dplat:*` | DM | UI глобальных фильтров (см. platform_settings.py docstring) |
| `mgr:global_filters` / `dev:global_filters` | DM | Вход из главного меню |

## Настройки по умолчанию

```python
PlatformConfig(
    enabled=True,
    max_age_hours=None,        # override time_threshold_hours, None = глобальный
    min_age_seconds=None,      # override MIN_ORDER_AGE_SECONDS
    min_budget=None,
    max_budget=None,
    include_no_budget=True,
    profiru=ProfiruFilters(max_response_price=None, only_remote=False, exclude_free=False),
    kwork=KworkFilters(category_ids=[11], min_hired_percent=None, min_offers=None, max_offers=None, exclude_portfolio_required=False, min_time_left_hours=None),
)
```

## Smoke-тест

1. Новая заявка приходит → появляется в группе `-1003648962522`
2. PM нажимает `✅ Взять себе` → карточка меняется на `pm_group_taken_kb` с "🔨 В работе: @pm"
3. Dev через `/dev → Заявки` видит новый assignment от PM
4. `/manager → Платформы → Глобальные фильтры → 🇷🇺 Профи.ру → Настроить → Бюджет` → задать `1000 10000` → заявки вне диапазона не попадают в очередь
