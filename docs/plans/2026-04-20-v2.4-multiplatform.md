# DevGrabBot v2.4 — Multi-Platform Parser + Per-User Preferences

**Дата:** 2026-04-20
**Статус:** В работе
**Инициатор:** Денис

## Цели

1. Добавить поддержку платформы **Kwork** (kwork.ru) как второго источника заявок.
2. Сделать парсерный слой универсальным — базовый контракт данных и оркестратор, независимый от конкретной платформы.
3. Дать каждому dev'у и PM'у возможность выбирать в настройках, с каких платформ получать заявки (Profi.ru, Kwork, или обе).
4. Визуально маркировать каждую заявку иконкой/лейблом источника везде — в нотификациях, панелях dev и manager.
5. **Параллельно** — переработать UX стоп-слов (массовый ввод, пагинация, экспорт/импорт) — см. отдельный трек.

## Не цели (YAGNI)

- FL.ru, Хабр.Фриланс, Upwork — не в этой версии.
- Полная абстракция `BaseFilters` — стоп-слова остаются в `ProfiruFilters` пока не появится третий парсер.
- Web UI для управления платформами — только Telegram-бот.
- Публичный API Kwork (которого нет) — работаем через `pykwork` (reverse-engineered mobile API).

## Архитектура

### Поток данных (без изменений в концепции)

```
[Profi.ru scraper]   ─┐
[Kwork scraper    ]   ─┼─→ Redis new_orders queue → AI Worker → DB + Redis analyzed
[{future} scraper]   ─┘                                          ↓
                                             Notification Worker → TG (dev/PM по platform-prefs)
```

### Единый контракт Redis dict (поле `platform` вместо `source`)

```python
{
    "platform": "kwork",           # ИЛИ "profiru"
    "external_id": "12345678",
    "title": "...",
    "description": "...",
    "raw_text": "...",
    "budget": "5000 ₽",
    "url": "https://kwork.ru/projects/12345678",
    "materials": None,              # Kwork не поддерживает, Profi.ru — list
    # + платформо-специфичные поля опционально
}
```

### База данных

**Order:**
- `platform` — перевести на `SourcePlatform` enum (`profiru`, `kwork`).
- `UniqueConstraint("platform", "external_id")` вместо `unique=True` на одном external_id.
- `url` — новая nullable колонка, URL заявки на платформе (для inline-кнопок).

**TeamMember (dev) и Manager:**
- `platforms: JSON[list[str]]` — default `["profiru", "kwork"]` — с каких платформ получать нотификации.

### Конфигурация

- `PROFIRU_LOGIN`, `PROFIRU_PASSWORD`, `PROFIRU_TOKEN` (уже есть, переименования не требуется из-за совместимости).
- `KWORK_LOGIN`, `KWORK_PASSWORD`, `KWORK_PHONE_LAST` (последние 4 цифры телефона — опционально).
- `KWORK_ENABLED=true`, `PROFIRU_ENABLED=true` — фичефлаги включения парсеров.
- `KWORK_RPS=2`, `KWORK_BURST=5` — rate limit.
- `KWORK_CATEGORIES=11` — CSV category IDs для фильтрации.
- `KWORK_POLL_INTERVAL_SEC=120` — опционально override общего `parse_interval_sec`.
- `PARSER_TOKEN_TTL_SEC` — общий (уже есть).

### Redis ключи — платформо-изолированные

- `devgrab:parser:profiru:token`, `devgrab:parser:profiru:cookies` (сейчас без платформы).
- `devgrab:parser:kwork:token`, `devgrab:parser:kwork:seen_ids`.
- Общая очередь `devgrab:new_orders` — одна на всех.

### URL-helper

```python
# src/bot/utils/platform_urls.py
def get_order_url(platform: str, external_id: str) -> str:
    match platform:
        case "profiru": return f"https://profi.ru/backoffice/n.php?o={external_id}"
        case "kwork":   return f"https://kwork.ru/projects/{external_id}"
        case _: raise ValueError(...)
```

## Риски и митигации

| Риск | Митигация |
|---|---|
| Kwork забанит аккаунт web-dusha | Residential proxy, 2 RPS rate limit, captcha-detection → pause. |
| Составной unique index ломает существующие Profi.ru заказы | Миграция проверяет уникальность `(platform, external_id)` до DROP старого constraint. |
| Profi.ru парсер ломается из-за рефакторинга | worker.py остаётся backwards-compatible, `_normalize()` меняется только в одной строке. |
| Pykwork 0.2.0 сломается без предупреждения | Version pinning + try/except на `KworkHTTPException`, alert в TG. |
| Утечка KWORK_PASSWORD в git | `.env.example` только с плейсхолдерами; memory с credentials; проверка `git status` перед каждым коммитом. |
